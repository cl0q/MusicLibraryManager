Decisions already made for W4-1 (record as IMP-067…070 if not yet in §4):
- **IMP-067** `album_tracks(album_id, track_id, disc INTEGER NOT NULL DEFAULT 1, position TEXT NOT NULL, track_number INTEGER, PRIMARY KEY (album_id, track_id))` with the same fractional `position` keys as `playlist_tracks` (`FractionalIndexer`, W3-PL's final rule). **Facts found in the code:** nothing in the app writes `tracks.album_id` today (only the Tauri era did; `TrackTagRepository` leaves it alone), the DB holds **no track or disc numbers**, and `MetadataExtractor.TrackMetadata` does not read them. So v50 (a) links every track with `album <> ''` and `album_id IS NULL` to an `albums` row found or created by (`COALESCE(NULLIF(album_artist,''), artist)` case-folded NFC, `title_normalized`) — DB only, no files; (b) seeds `album_tracks` for every track with an `album_id`, disc 1, ordered by title, `track_number NULL`. Track/disc numbers come later from files: `MetadataExtractor` gains `trackNumber`/`discNumber` (ffprobe/AVFoundation `track`/`disc` tags), the import path writes them into the join for new tracks, and a maintenance operation **`Read Track Numbers`** (Library ▸ Maintenance ▸ …, Activity operation, drive-waiting, resumable) fills `track_number`/`disc` for existing albums and re-sorts positions where numbers are complete. Manual cascade: delete a track → delete its rows; delete an album → delete its rows.
- **IMP-068** v51 dedup: albums whose (album_artist case-folded NFC, title_normalized) match are merged into the row with the most tracks (ties: lowest id); `tracks.album_id`, `album_tracks`, `user_album_variant_pref` and `variant_of` are re-pointed; the losing rows are deleted; a pre-migration backup must exist (the launch coordinator makes one — verify with the real migrator on a copy in tests, as W3-LAUNCH did).
