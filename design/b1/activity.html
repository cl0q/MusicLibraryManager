Activity: toolbar item, popover and Activity window — Tier 2

Try: click the live Activity item in the first exhibit to open the real popover; expand the download batch (▸) inside it · in the Activity window switch Operations · Logs, use the filters All · Running · Needs attention · Finished, click a row to see its detail, Show in Logs jumps to the log lines of that operation · right-click a row · Clear Waiting… on the analysis row opens the confirmation · in Logs: level and source filters (remembered across reloads), search, Pause / Resume, Wrap lines, Clear…, Export…, Copy, right-click the text · State switches the window between Default, Empty, Loading, Error and No library open · Variant B shows the bottom-strip alternative.

Rule (DEC-044): every job slower than about 2 s is an Activity operation with a subject link, a result that survives relaunch, and only the controls that are true. The place that started a job shows a short echo with the same numbers and words. Decisions: DEC-005, DEC-044, DEC-016, DEC-037.

Variant A (recommended): toolbar item + popover + window. For: calm when idle; failures stay visible as words in the toolbar; frees 36 pt of height in every view; the window exists without a library, so Logs are reachable when a library can’t open. Against: running work is one click away instead of always listed — mitigated by the item’s text (Downloading 12 of 44).

Variant B (kept for comparison): a status-bar-height strip at the bottom of the main window that expands upward. For: always visible; familiar from today; more room for several jobs in one line. Against: costs height in every view and competes with the status bar and the selection bar for the bottom edge; not available on launch screens (no main window content); an expanding panel pushes content — the “nothing moves unless you ask” principle suffers; a second place for text next to the status bar.

Toolbar Activity item P-ACTIVITY

Idle P-ACTIVITY

Plain icon. No text, no dot. Click still opens the popover (Recent, last backup).

Running P-ACTIVITY

Determinate ring + the most important job in words with its count. Several jobs: the one the user started last, then +2.

Needs attention P-ACTIVITY.N01

Nothing running, but something failed or waits for the user. The words stay until fixed or dismissed — never only a colour.

Running and needs attention — live P-ACTIVITY

Both. Click it to open the popover. At narrow window widths the running text collapses to the ring first; the attention text stays.

Activity popover P-ACTIVITY-OPS in the popover

Nothing happening

One line, plus the fact people open it for when idle: when the last backup ran.

Several jobs running

One row per operation (a sync is one row, not two). The download batch expands into per-track rows — click ▸. Controls say what they really do.

Needs attention — grouped by cause, with the fix

Hundreds of failures become a few causes. Each group has the one action that fixes it; waiting groups resume by themselves.

Recent — results stay

Finished operations keep their result sentence and survive a relaunch. A click opens the subject (playlist, profile, Review…).

Job kinds W-ACTIVITY.N01

State words G-JOB-STATUS

Exactly six, always as text in the State column: Queued (accepted, waiting for its turn or for a condition — the reason is in Progress) · Running · Paused (by the user, or by MLM with the reason: Waiting — paused while downloads run) · Completed (may carry failures in its result: 35 downloaded · 9 failed) · Failed (nothing was achieved; cause + one action) · Cancelled. Per-track rows use the track glossary: Downloaded, Downloading…, Queued, Download failed, Skipped — already downloaded. No lowercase enum names, no Stalled.

Quitting or switching library with running work A-LIB-SWITCH

The alert takes its list from Activity: it names what stops and what continues later. Designed on launch.html#switch; quitting uses the same alert with Quit. Downloads and syncs stop after the current track or file and are listed as Cancelled with Run Again; the analysis queue and waiting tag changes are stored and continue at the next launch.

Switch to “Laptop Subset”?

1 import and 1 sync will stop after the current track. 212 waiting analyses continue the next time “Main Library” is open.
