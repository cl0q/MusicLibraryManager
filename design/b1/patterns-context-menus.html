Context menus — Tier 3 pattern catalogue

What this is: the one rule for every context menu and every More (•••) menu, then every context menu of today’s app (18 inventory CM- IDs) with what it was and what it becomes, then the menus the redesign adds, then the four shared submenus. Menus are drawn open and static; press A to see IDs, C to comment on a menu or a single item. Each card links to the page where the menu can be opened for real (right-click there).

Decisions: DEC-039 (group order), DEC-008/009 (Play, Preview), DEC-014 (drive not connected), DEC-022 (More menu = context menu), DEC-023 (Refresh from ‹Source›), DEC-041 (Undo instead of confirmations). THOUGHTS §4.4.

Item IDs: .E0x = the item exists today under that number in the inventory, .N0x = new item.

Rules

Every context menu and every More menu uses the same seven groups in the same order. A menu is a subset of this list, never a reordering.

Count as a header line PATTERN-CM.N03

With more than one subject the menu starts with a disabled header line: 3 tracks, 2 playlists, 3 genres — as Finder does. Item labels never carry the count (Add to Playlist (3 tracks) is gone).

The header is also where a window-level reason goes: “Lexxar” is not connected. A count appears inside a label only when the item applies to part of the selection: Download 1 Not-Downloaded Track.

Words PATTERN-CM.N04

  • Verbs in Title Case, as macOS menus are: Show in Finder, Add to Playlist, Remove from Library…. (THOUGHTS §4.4 says “sentence case”; the packet follows the macOS menu convention that AUTHORING.md prescribes — see the report.)
  • An ellipsis (…) only when the command asks for more before it acts: a sheet, a file panel or a confirmation.
  • Glossary words only: Download, Retry Download, Refresh from SoundCloud (never “Sync” for a playlist), Show in Finder (never “Reveal”), Add to Sync Profile (never “Sync to”).
  • Container names are real: Remove from “Warm-up” in a list of mixed containers, Remove from Playlist inside one playlist.
  • Shortcuts are shown next to the item when one exists (↩ Space ⌘I ⌘D ⇧⌘R ⌫ ⌘⌫) — the context menu teaches the keyboard.
  • No icons except where the page already uses one for Play and Download; never an icon as the only label.
  • Feedback: an item that changes something silently confirms in the status bar with Undo; nothing navigates unless the verb says so (Open, Go to…, Show…).

Destructive last and separated PATTERN-CM.N05

The Remove group is always the last group. Inside it the reversible removal comes first (Remove from Playlist ⌫, undoable, no question) and the irreversible one last, in the destructive colour, with an ellipsis because it always asks (Remove from Library… ⌘⌫, Delete Playlist…).

Where removing from the library would be a surprise it does not exist at all: in the Queue, in Review version rows it is the last item, in a sync profile only Remove from “iPod Classic”.

Remove from Playlist⌫Remove from Library…⌘⌫

The same menu behind every More button PATTERN-CM.N06 DEC-022

A More (•••) button in a header and the context menu of the same thing are built from the same list. More leaves out what the header already shows as buttons (Play, Shuffle) and may add commands that only make sense in the detail view (Import M3U into This Playlist…, Edit Order).

The selection bar’s More (P-SELBAR.N05) is the multi-selection track menu, minus the four actions the bar shows as buttons.
