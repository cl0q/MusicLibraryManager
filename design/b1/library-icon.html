The .mlibm library-file icon — concept (THOUGHTS §7.19, DEC-033, A0-LIBRARY-DEFINITION D9)

A library is one file package in Finder, so it needs a document icon that reads as “an MLM library” — a collection — and not as “MLM itself”. Three concepts, each at 256, 64, 32 and 16 px on a light and a dark backdrop. A (record crate) is recommended. The Variant switch in the review bar changes which concept is used in the in-context samples below (Finder list and icon view, File ▸ Open Recent, the library picker). Dark switches the surrounding UI; the artwork itself does not change with the theme.

These are concept drawings in inline SVG, not final artwork: the disc with the tinted label is a placeholder for the app icon’s mark, and the tint uses the accent colour as a stand-in for the app icon’s colour. Question Q8 in THOUGHTS §9.

A — Record crate ICON-MLIBM/A Recommended

Three sleeve edges fanned behind a front sleeve with the mark, in a crate with a handle slot. A collection, portable, one object. The stepped top and the wide base keep the silhouette legible down to 16 px, where it is still clearly not a plain document and not the app.

B — Stacked sleeves ICON-MLIBM/B

Three sleeves stacked diagonally, a record sliding out of the front one. Pleasant at 256 px; at 16 px it turns into overlapping squares (the system’s “several documents” look) and says “album” more than “library”.

C — Document with folded corner + mark ICON-MLIBM/C

The system document shape carrying the mark. Conventional and unmistakably a file — but generic: it does not say “collection”, and it leaves no distinct shape for other MLM documents later (an exported playlist, a backup).

Rules for the asset ICON-MLIBM.N05

RuleWhy
Static .icns, the same for every library — not per-library artwork.A per-file icon rendered from a library’s covers would live in extended attributes / a resource fork, which many copy, sync and backup tools silently drop. The static document icon is registered once in the app bundle and survives every copy. The library’s identity is its name (file name, window subtitle, sidebar footer); its state is always text (“Not connected — on ‘Lexxar’”), never drawn into the icon.
Reads as “an MLM library”, not “MLM”.Derived from the app icon’s visual language (same mark, same tint) but a different object and silhouette, so the Dock icon and a library file are never confused. Document-like footprint: it sits next to other files in Finder.
Small sizes are redrawn, not scaled.16 and 32 px use a simplified drawing (fewer sleeve edges, no grooves, thicker edges) aligned to the pixel grid — shown above. The .icns carries 16, 32, 128, 256 and 512 pt at 1× and 2×.
Restrained colour.Neutral greys plus the one tint of the app icon. No source brand colours, no state colours, no text. The artwork is fixed (it does not follow light/dark or the accent colour); it must hold on light and dark backdrops and on a selection highlight — check the selected rows above.
Used wherever a library is named as a file.Finder, Open and Save dialogs, File ▸ Open Recent, the library menu in the sidebar footer, the library picker, the switch-library alert, drag previews of a .mlibm file. Read from the system (NSWorkspace.shared.icon(forFile:)) so the app and Finder always agree.
