<task type="auto">
  <name>Create library-only and remote-only query functions</name>
  <files>src-tauri/src/search/query.rs</files>
  <action>
Add query functions for filtered library/remote views.

1. Create get_library_tracks_only function:
   - Copy get_all_tracks implementation
   - Add WHERE clause: WHERE organized_path IS NOT NULL
   - ORDER BY date_added DESC
   - Return DbResult<Vec<Track>>

2. Create get_remote_tracks_only function:
   - Copy get_all_tracks implementation
   - Add JOIN and WHERE clause:
     SELECT DISTINCT t.*
     FROM tracks t
     INNER JOIN track_sources ts ON t.id = ts.track_id
     WHERE t.organized_path IS NULL
     ORDER BY t.date_added DESC
   - This ensures remote tracks actually have streaming source associations (avoids orphaned tracks from pitfall #1 in research)
   - Return DbResult<Vec<Track>>

3. Create count_remote_tracks function:
   - Use same JOIN logic as get_remote_tracks_only:
     SELECT COUNT(DISTINCT t.id)
     FROM tracks t
     INNER JOIN track_sources ts ON t.id = ts.track_id
     WHERE t.organized_path IS NULL
   - Return DbResult<i64> for badge count

Keep existing get_all_tracks and search_tracks unchanged (backward compatibility).
  </action>
  <verify>cargo test -p music-library-manager --lib search::query</verify>
  <done>Query functions exist: get_library_tracks_only returns local files only, get_remote_tracks_only returns streaming tracks with source associations, count_remote_tracks returns integer count</done>
</task>
