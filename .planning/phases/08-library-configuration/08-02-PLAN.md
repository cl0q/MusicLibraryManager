Implement OS-level mount detection so the app knows when the configured library drive connects or disconnects. Uses macOS FSEvents to listen for volume mount/unmount events and emits Tauri events to the frontend.

Purpose: Without mount detection, the app cannot gracefully handle drive disconnection (LCFG-02). This service runs in the background and emits events that the UI layer (Plan 03/04) consumes to show/hide library content.

Output: `mount/` module with MountDetector service, FSEvents integration, and startup integration. Frontend receives `library-mount-changed` events with connected/disconnected state.
</objective>

**Cargo.toml:**

Add the `notify` crate for cross-platform filesystem watching. On macOS, `notify` uses FSEvents internally, which supports mount/unmount detection. This avoids pulling in the lower-level `fsevent` crate directly.

```toml
notify = { version = "6", features = ["macos_fsevent"] }
```

NOTE: Research suggested `fsevent` crate directly, but `notify` 6.x wraps FSEvents on macOS and provides a cleaner API. The `macos_fsevent` feature ensures FSEvents backend is used (not kqueue). If `notify` does NOT surface mount/unmount event flags, fall back to monitoring `/Volumes` directory for create/delete events (a volume appearing/disappearing in `/Volumes` indicates mount/unmount). This is the pragmatic approach.

**Mount module (mount/mod.rs):**

```rust
pub mod detector;
pub use detector::{MountDetector, LibraryMountState};
```

**Mount detector (mount/detector.rs):**

Create `LibraryMountState` enum:
```rust
#[derive(Clone, Debug, Serialize)]
pub enum LibraryMountState {
    Connected,
    Disconnected,
    NotConfigured,
}
```

Create `MountDetector` struct:
- Fields: `state: Arc<RwLock<LibraryMountState>>`, `library_root: PathBuf`
- `new(library_root: PathBuf) -> Self`: Initialize with Connected if path exists, Disconnected otherwise
- `get_state(&self) -> LibraryMountState`: Read current state
- `start(app_handle: tauri::AppHandle, library_root: PathBuf) -> Result<Arc<Self>, String>`:
  1. Create detector instance
  2. Check initial mount state by verifying library root exists
  3. Spawn background thread that watches `/Volumes` using `notify::RecommendedWatcher`
  4. On filesystem events in `/Volumes`:
     - Check if `library_root` path exists (simple Path::exists() check)
     - If state changed from previous: update `Arc<RwLock<LibraryMountState>>`
     - Emit `library-mount-changed` event to frontend via `app_handle.emit("library-mount-changed", &new_state)`
  5. Return Arc<Self> so it can be stored in Tauri managed state

**Watching strategy:**

The simplest reliable approach for macOS: watch `/Volumes` directory for create/remove events. When a volume is mounted, a new directory appears in `/Volumes`. When unmounted, it disappears. After any event in `/Volumes`:
1. Check if `library_root.exists()`
2. Compare with previous state
3. Emit event if changed

This avoids needing low-level FSEvents mount flags. The `notify` crate's `RecommendedWatcher` with `RecursiveMode::NonRecursive` on `/Volumes` captures mount/unmount as directory create/remove events.

**Error handling for mid-operation failures (per locked decision):**

When library root disappears (mount state transitions to Disconnected), emit both:
- `library-mount-changed` event with Disconnected state
- A separate event or include a message field so frontend can show toast: "Library drive disconnected"

**Tauri managed state:**

The MountDetector (wrapped in Arc) should be stored as Tauri managed state so commands can query mount state. Add `app.manage(mount_detector_arc)` in startup.

**startup.rs updates:**

Add a new function `setup_mount_detection(app_handle: tauri::AppHandle)`:
1. Get database connection (same pattern as other startup functions)
2. Load `LibraryConfig` from database
3. If not configured: log info "Library not configured, skipping mount detection", emit `library-mount-changed` event with `NotConfigured` state, return
4. Check if library root currently exists:
   - If yes: log "Library drive connected at {path}"
   - If no: log warn "Library drive not currently connected", emit `library-mount-changed` event with `Disconnected`
5. Call `MountDetector::start(app_handle.clone(), config.root_path.unwrap())`
6. Store returned `Arc<MountDetector>` in Tauri managed state via `app_handle.manage(detector)`
7. If mount detection start fails: log error, do NOT block app startup

**lib.rs setup changes:**

In the `.setup(|app| { ... })` closure, the mount detection needs `AppHandle`. Currently the setup spawns async tasks. Add mount detection initialization:

After the existing startup task spawn, add another spawn for mount detection. The mount detector needs to be initialized in the setup closure (not the spawned async task) because `app.manage()` must happen during setup.

Approach: Call `setup_mount_detection()` synchronously during setup (it internally spawns the async watcher thread). The function should:
- Load config from DB (synchronous rusqlite call is fine during setup)
- If configured: create MountDetector (synchronous creation), spawn watcher thread (async/background), manage state
- This keeps setup fast while watcher runs in background

Update the setup closure to call mount detection setup after existing startup task is spawned.
