# Phase 38 — UI Design Contract

> Visual and interaction contract for macOS native SwiftUI sync surfaces.
> Locks visual and interaction decisions for Folder & Device Sync (v2.0 macOS Native).
> Generated by gsd-ui-researcher, verified against CONTEXT.md (D-01..D-14 UI decisions).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native macOS SwiftUI) |
| Preset | not applicable |
| Component library | SwiftUI + AppKit (NSOpenPanel, NSWorkspace) |
| Icon library | Apple SF Symbols (system-bundled) |
| Font | System (San Francisco) via SwiftUI — inherited from Phase 36 MLMFont tokens |
| Theme tokens (color) | `macos-app/MLM/Theme/Colors.swift` — `Color.mlmBase`, `.mlmSurface`, `.mlmRaised`, `.mlmEdge`, `.mlmInk`, `.mlmInkSecondary`, `.mlmInkMuted`, `.mlmAccent`, `.mlmError`, `.mlmWarning` |
| Theme tokens (type) | `macos-app/MLM/Theme/Typography.swift` — `MLMFont.body`, `.bodyBold`, `.sectionLabel`, `.sectionHeader`, `.muted`, `.badge` |

**Native-look mandate** (from project MEMORY): Little Snitch / Google Maps / Apple stock app aesthetic. No bespoke palette. All colors delegate to `NSColor` / `Color.accentColor` so Light/Dark mode + Accessibility settings adapt automatically.

## Spacing Scale

Multiples of 4 only. Inherited from Phase 36 Solar design system.

| Token | Value | Usage in Phase 38 |
|-------|-------|-------------------|
| xs | 4px | Icon spacing, inline gaps |
| sm | 8px | Compact element spacing (button labels + icon, content row gaps) |
| md | 16px | Default padding, section spacing, Settings-Form fields |
| lg | 24px | Major section breaks, Profile-Detail section headers |
| xl | 32px | Content section top-padding, settings panel boundaries |
| 2xl | 48px | Reserved (unused) |
| 3xl | 64px | Reserved (unused) |

**Exceptions:** None. All Phase 38 surfaces follow 4px multiples.

**Surface-specific dimensions:**

- **Settings-Form Section**: 16px horizontal padding, 8px vertical gap between toggles and picker.
- **Picker-Sheet List rows**: 8px vertical inset (standard SwiftUI `List` density).
- **Content-Section headers** ("Playlists (N)", "Tracks (N)"): 16px top-padding, 12px bottom-padding (section label spacing).
- **Trash icon on hover**: 8px right-margin, appears on row hover.
- **Progress-Section linear bar**: full-width minus 16px horizontal padding, 8px height (standard SwiftUI `ProgressView`).
- **Failed-tracks DisclosureGroup row**: 8px vertical, 12px left-indent per item (standard SwiftUI `DisclosureGroup`).
- **Toolbar indicator**: 12px horizontal inset from trailing edge, 8px spacing from other toolbar items.

### Surface 2: SyncSettingsForm (NEW)

Collapsible Form in SyncProfileDetailView.

**Title:** "Settings" (section label)

**Expanded state default:** false (collapsed by default; expanding reveals toggles)

**Fields (in order):**

1. **Toggle: Generate M3U8**
   - Label: "Generate M3U8 Playlists"
   - State: `profile.generate_m3u8`
   - Purpose: Controls whether Rockbox playlist files are written
   - Default for new Folder profile: false
   - Default for Device profile (smart-detect): true
   - OnChange: trigger VM `updateProfileSettings(...)` + `loadPreview()`

2. **Picker: Transcode Mode**
   - Label: "Transcode Mode"
   - Options:
     - "Keep Originals" (value: `keep_originals`)
     - "248 kbps AAC" (value: `aac_248`)
     - "320 kbps AAC" (value: `aac_320`)
   - State: `profile.transcode_mode`
   - Default for new Folder profile: `keep_originals`
   - Default for Device profile (smart-detect): `aac_248`
   - OnChange: trigger VM `updateProfileSettings(...)` + `loadPreview()`
   - Note: "Keep Originals" means files are hardlinked/copied as-is (no transcode); 248/320 modes invoke TranscodeService with bitrate param

3. **Toggle: FAT32-Safe Paths**
   - Label: "FAT32-Safe Filenames"
   - State: `profile.fat32_safe_paths`
   - Purpose: Controls PathSanitizer application (strips invalid chars for FAT32)
   - Default for new profiles: true (always-on)
   - OnChange: trigger VM `updateProfileSettings(...)` + `loadPreview()`

4. **Toggle: Clean Up Removed Files**
   - Label: "Delete Removed Files from Destination"
   - State: `profile.cleanup_removed_files`
   - Purpose: Controls whether files in `preview.filesToRemove` are actually deleted from disk (vs just clearing DB row)
   - Default for new Folder profile: true
   - Default for Device profile (smart-detect): true
   - OnChange: trigger VM `updateProfileSettings(...)` + `loadPreview()`

**Layout:**
```
┌─ Settings ▼ ─────────────────────┐
│                                  │
│ Toggle: Generate M3U8            │ 8px spacing between
│ Toggle: FAT32-Safe Filenames     │
│ Picker: Transcode Mode ▼         │ Picker expands to 120px
│ Toggle: Clean Up Removed Files   │
│                                  │
└──────────────────────────────────┘
```

**Styling:**
- Section background: `Color.mlmSurface`
- Toggle/Picker label: `MLMFont.body`, `Color.mlmInk`
- Picker dropdown: standard SwiftUI style
- Divider above Settings (if expanded): `Color.mlmEdge`

## Interaction Patterns

### Pattern 1: Multi-Select in Pickers & Content Sections

**Behavior:**
- Click row: select that row (highlight with `Color.mlmRaised` background)
- Shift+Click: range-select from last-selected to clicked row
- Cmd+Click: toggle-select (add to or remove from selection)
- All selections persist until "Add" / "Remove" button is clicked or sheet is dismissed

**Visual feedback:**
- Selected rows: `Color.mlmRaised` or `Color.mlmAccent.opacity(0.2)` background
- Checkboxes: SwiftUI native, visible on all rows, checked when selected
- Bulk action button: enabled only when 1+ rows selected, shows count ("Remove (N)")

---

### Pattern 2: Hover-Trash Icon

**Behavior:**
- Rows in Content-Sections (Playlists, Tracks) show trash icon only on hover
- Click trash: immediately remove (no confirmation — matches Playlist-Detail pattern from Phase 36)
- Trash color: `Color.mlmError` on hover, hidden at rest

**Implementation:** Use `.onHover { isHovering in ... }` to toggle opacity of trash icon.

---

### Pattern 3: Search-Filter (Immediate, No Debounce)

**Behavior:**
- As user types, filter results update in real-time
- No debounce (results appear instantly)
- Case-insensitive matching
- Works for both artist+title (tracks) and name (playlists)

**Implementation:** Use SwiftUI `@State var searchText` + `.onChange(of: searchText)` to filter the list source.

---

### Pattern 4: Context Menu Submenu

**Behavior:**
- Menu "Sync to ▸" appears alongside other menu items
- Submenu shows list of profiles
- Click profile name: execute action + dismiss menu
- If no profiles: submenu shows "Create New Profile…" only

**Implementation:** Nested `Menu { ForEach(profiles) { Button } }` structure.

---

### Pattern 5: Notification Post & Observe

**Behavior:**
- After mutation (addPlaylists, removeTrack, etc.), ViewModel posts `.syncProfileDidChange` notification
- SyncProfileDetailView observes notification via `.onReceive(.syncProfileDidChange)` → reload preview + refresh content sections

**Implementation:** Use `NotificationCenter.default.publisher(for: Notification.Name.syncProfileDidChange)` in a `.onReceive()` view modifier.

## Validation Architecture

### SyncViewModel Method Signatures

All async methods in `SyncViewModel` follow this pattern:

```swift
@MainActor
func addPlaylists(_ playlistIds: [Int64]) async {
    // 1. Call repository add methods (GRDB INSERT OR IGNORE)
    // 2. Post .syncProfileDidChange notification
    // 3. Reload preview for UI update
}
```

Rationale:
- `INSERT OR IGNORE` idempotency means playlists can be added multiple times without error
- Notification pattern enables cross-view refresh (Pickers can be dismissed; detail re-fetches)
- Separate reload-preview call allows UI to reflect disk-space impacts immediately

### SyncService Validation

- **Transcode mode validation:** Enum `TranscodeMode` (at compile-time); invalid modes rejected by Swift type system
- **Output folder validation:** NSFileManager checks folder exists and is writable before create; reports error in Result-Section if creation fails
- **File deletion validation:** Try `FileManager.trashItem()` first (APFS/HFS+), fall back to `removeItem()` on EXDEV/EPERM (FAT32/exFAT)

## Appendix: Open Questions Resolved

### D-11 — Toolbar Indicator Hosting

**Phase 37 analog:** ArtworkBackfillService does NOT currently have a visible toolbar indicator (verified via codebase grep). This creates a design gap: D-11 says "analog to Phase 37" but the analog doesn't exist visually.

**Phase 38 decision:** Implement toolbar indicator in `ContentView.toolbar` `.primaryAction` slot (top-right corner). Design from scratch per this contract (Surface 8). Recommendation: spinner + counter visible during sync, hidden when done.

### D-02 — Settings-Form Collapse Default

**Decision:** Settings-Form defaults to **collapsed** (`DisclosureGroup(isExpanded: false)`). User can expand to view/edit toggles. This reduces cognitive load on first profile-detail view.

### D-05 — "Sync to ▸" Submenu Availability

**Decision:** If no sync profiles exist, submenu shows only "Create New Profile…" entry. This allows users to create a profile on-the-fly without navigating back to SyncView.

### D-07 — Content-Section Default State

**Decision:** Both "Playlists (N)" and "Tracks (N)" sections default to **collapsed** (DisclosureGroup expanded: false) on first view. This matches Apple Music / Finder pattern and reduces visual clutter when profiles have many items.

### D-14 — Cancellation Granularity

**Implementation:** Cancellation flag is checked **between files** in the `executeSync` loop, not mid-transcode subprocess. If transcode is running, it completes before the next flag-check. This ensures clean `sync_state` updates per-track and avoids orphaned partial files.
