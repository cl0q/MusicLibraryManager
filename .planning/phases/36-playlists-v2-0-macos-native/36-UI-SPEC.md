## Spacing Scale

Multiples of 4 only. Phase 36 reuses the existing card surface (`PlaylistCard.swift`) so spacing already aligns with this scale.

| Token | Value | Usage in Phase 36 |
|-------|-------|-------------------|
| xxs | 2px | Inner padding for rename TextField (`PlaylistCard.swift:118`) |
| xs | 4px | Mosaic tile gap (see Cover-Card contract); info-area row gap (already used at `PlaylistCard.swift:110`); icon-text gap |
| sm | 8px | Compact element spacing; sidebar row padding; banner inner padding |
| md | 12px | Card grid item spacing (`PlaylistsView.swift:30`); card info-area padding (`:144`); header bar vertical padding (`:146`) |
| lg | 16px | Header bar horizontal padding (`:145`); grid container padding (`:227`); empty-state vertical spacing |
| xl | 24px | DisclosureGroup label-to-content vertical breathing room |
| 2xl | 32px | Reserved (unused in Phase 36) |
| 3xl | 64px | Reserved (unused in Phase 36) |

**Cover-card dimensions:**
- Card icon area (cover render region): **100 pt height** (preserves the existing card; matches `PlaylistCard.swift:72`).
- Card width: adaptive 200–260 pt (matches `PlaylistsView.swift:29`).
- Card corner radius: **8 pt** (matches `PlaylistCard.swift:42`).

**Mosaic-tile geometry (2×2):**
- Source PNG: **512×512 px**, centered crop, scaled with `aspectRatio(.fill)`.
- Per-tile size in the source PNG: **256×256 px** (half on each axis).
- Inter-tile gap: **2 px** in source PNG (≈1 pt on-screen after downscale to a 100-pt card area). Tile gap color: `Color.mlmBase` (window background) — reads as a thin "letterbox seam".
- Tile corner radius: **0 px** in source PNG. The outer card already clips to 8 pt; individual tiles stay square so the 2×2 grid reads as one cohesive mosaic, not four chiclets.

**Sidebar disclosure-group geometry:**
- Indent of pinned rows under `Playlists` header: rely on SwiftUI `DisclosureGroup` default indentation. Do NOT manually pad — that diverges from Finder / Apple Music behavior.
- Pinned-row height: matches sibling sidebar items (let `List(selection:)` size them naturally).
- Disclosure chevron: default SwiftUI styling (no custom override).

**Exceptions:** Mosaic gap of 2 px in the source PNG is sub-4-px but is in *pixel space* of the cached PNG, not pt space of the layout. The on-screen pt-equivalent rounds to ≤1 pt seam — well below the 4-pt rule's intent. Documented here so the checker doesn't flag it.

## Typography

Phase 36 uses **exactly 4 type tokens**, all already defined in `MLMFont`. No new font sizes are introduced.

| Role | MLMFont Token | Resolved | Weight | Usage in Phase 36 |
|------|--------------|----------|--------|--------------------|
| Body | `MLMFont.body` | `Font.body` (~13 pt system) | regular (400) | Default text in cards, sidebar rows, banner |
| Body Bold | `MLMFont.bodyBold` | `Font.body.weight(.semibold)` | semibold (600) | Playlist name on cards (`PlaylistCard.swift:115,125`), New Playlist button label, sidebar pinned-row name |
| Caption (muted) | `MLMFont.muted` | `Font.caption` (~11 pt) | regular (400) | "{n} tracks" sub-line, banner sub-copy |
| Page Title | `MLMFont.pageTitle` | `Font.title2.weight(.semibold)` (~17 pt) | semibold (600) | Playlists grid header ("Playlists") at `PlaylistsView.swift:82` (unchanged) |

**Gradient-fallback cover initials (D-03):**
- Token: `Font.system(size: 96, weight: .bold, design: .rounded).monospacedDigit()` rendered into a 512×512 PNG (so 96 pt at 2× = visually large enough to read at the 100-pt card and at full-resolution detail-view hero).
- Color: `NSColor.white.withAlphaComponent(0.95)` — high-contrast over any gradient.
- Characters: first 2 grapheme clusters of `playlist.name`, uppercased via `String.localizedUppercase`. Handles emoji/non-Latin gracefully ("🎵 Workout" → "🎵W"; "やる気" → "やる").
- Single-character names fall back to 1 letter (no padding).

**Line heights:** SwiftUI manages line height automatically per text style. Do not override — overriding `lineSpacing` here would diverge from native macOS behavior.

## Color

Solar/macOS-native palette. Phase 36 introduces **zero new color tokens**; everything maps to existing `Color.mlm*` aliases that delegate to `NSColor` system tokens.

### 60 / 30 / 10 Split

| Role | Token | Adapts To | Usage in Phase 36 |
|------|-------|-----------|--------------------|
| Dominant 60% | `Color.mlmBase` (= `NSColor.windowBackgroundColor`) | Light + Dark + High Contrast | Window chrome, grid container background (`PlaylistsView.swift:74`), gap-seam between mosaic tiles, banner background |
| Secondary 30% | `Color.mlmSurface` (= `NSColor.controlBackgroundColor`) and `Color.mlmRaised` (= `NSColor.underPageBackgroundColor`) | Light + Dark | Playlist card surface (`PlaylistCard.swift:41`), sidebar background, search-field background, count-badge background |
| Accent 10% | `Color.mlmAccent` (= system `Color.accentColor`, user-controlled in System Settings → Appearance) | All modes + user preference | **Reserved for:** New Playlist button (`PlaylistsView.swift:136`), drop-target border on cards (drag-hover), currently-selected sidebar row highlight (SwiftUI native), focus rings on rename text field |

### Destructive & Status

| Role | Token | Adapts To | Usage in Phase 36 |
|------|-------|-----------|--------------------|
| Destructive | `Color.mlmError` (= `Color.red` → system semantic red) | Light + Dark | Delete-Playlist confirmation only (already in `PlaylistCard.swift:177-181`); not used for the pin-limit banner (see Warning) |
| Warning | `Color.mlmWarning` (= `Color.orange` → system semantic) | Light + Dark | Pin-limit hint banner left border + icon |
| Active/Info | `Color.mlmActive` (= `Color.blue`) | Light + Dark | Reserved for smart playlists (existing); not new in Phase 36 |
| Liked | `Color.mlmError` opacity | Light + Dark | Liked-playlist heart icon (existing) |

### Accent reserved for (explicit list — never "all interactive elements"):

1. **Primary CTA only** — "+ New Playlist" button (`PlaylistsView.swift:136`).
2. **Drop-target visual feedback** — when the user drags an image file over a `PlaylistCard`, the card's overlay stroke flips from `Color.mlmEdgeSubtle` to `Color.mlmAccent` with `lineWidth: 2` (up from 1). Animation: `withAnimation(.easeInOut(duration: 0.12))`. State: tracked via `isTargeted` binding on `.onDrop`.
3. **Currently-selected sidebar row** — handled natively by `List(selection:)` selection-highlight (SwiftUI uses `Color.accentColor` automatically). Do not override.
4. **Focused rename TextField** — SwiftUI default focus ring (system-managed; uses accent).

**NOT accent:** card hover state (uses `Color.mlmRaised`, not accent), pin icon (uses `.white.opacity(0.9)` over gradient), source badge, mosaic tile borders, sidebar disclosure chevron.

### Cover-Image Gradient Palette (D-02 + D-03)

The fallback-cover gradient and the mosaic gap-tile gradient must draw from the Solar palette — **no rainbow gradients**, no Apple-Music-2024-style hue cycle.

**Deterministic palette indexed by `playlist.id` hash** (research recommendation):

```
gradientIndex = abs(playlist.id) % 4

Index 0 → [NSColor.controlAccentColor,                        NSColor.controlAccentColor.blended(.darkGray, 0.4)]
Index 1 → [NSColor.systemBlue,                                NSColor.systemIndigo]
Index 2 → [NSColor.systemTeal,                                NSColor.systemBlue.blended(.black, 0.3)]
Index 3 → [NSColor.systemGray,                                NSColor.controlAccentColor]
```

**Rationale:**
- All 4 variants land in the cool/neutral zone (blue / teal / indigo / accent / gray). No reds, oranges, yellows, pinks, purples — keeps the look "Little Snitch + Apple Music sidebar," not "kids' app."
- `NSColor.controlAccentColor` is included so each playlist library has at least 2-of-4 covers that honor the user's chosen system accent.
- Deterministic (hash of `playlist.id`) → cover stays visually identical across regenerations until the user explicitly resets.

**Mosaic gradient gap-tile** (D-02 fill rule):
- When a 2×2 slot has no artwork (track count < 4 or track has no embedded art), fill with a `LinearGradient` derived from the **dominant color of the diagonally-opposite tile** if available, else from the playlist palette above.
- Direction: `startPoint: .topLeading, endPoint: .bottomTrailing`.
- This keeps the mosaic feeling like one piece rather than 4 unrelated stickers.

**Fallback gradient (D-03, 0 embedded artwork):**
- Full-card `LinearGradient` from the playlist palette above.
- Direction: `startPoint: .topLeading, endPoint: .bottomTrailing`.
- Initials (2 chars) centered, `Color.white.opacity(0.95)`, rounded bold font (see Typography).

## Interaction Contracts

### Cover-Card states (Card.iconArea, 100 pt tall)

| State | Visual |
|-------|--------|
| **Cached PNG present** | `Image(nsImage: cachedNSImage)` with `.aspectRatio(.fill)` and `.clipped()`; pin-indicator & source-badge stay overlaid on top |
| **No cache yet (loading transitional)** | Existing `LinearGradient` + SF Symbol icon fallback (kept for first paint until service finishes generating). No spinner — gracefully degrades. |
| **Drag-hover (drop-target active)** | Overlay stroke flips: `Color.mlmEdgeSubtle, 1pt` → `Color.mlmAccent, 2pt`. Animation `.easeInOut(0.12)`. NO scale, NO shadow — pure border feedback. |
| **Drop-accepted (transient flash)** | After file accepted, brief 1× pulse: stroke goes accent at `lineWidth: 3` for 200 ms then settles back to hover state. SwiftUI `withAnimation` chain. |
| **Drop-rejected (bad file)** | Stroke flips to `Color.mlmError, 2pt` for 400 ms, then returns to `mlmEdgeSubtle`. Banner above grid surfaces the error message. |

### Direct-to-Detail click transition (D-09)

**Decision:** Instant-jump, no fade, no slide. Apple Music's sidebar behavior is instantaneous.

- Click pinned-sidebar row → `selectedSection = .playlistDetail(id)` → SwiftUI re-renders `ContentView.detailView` (the entire detail body is the new view).
- **No grid-flash:** The grid is never rendered when sidebar-click is the entry path. `PlaylistsView` is bypassed entirely; the route goes through `PlaylistDetailViewLoader` directly.
- **Sidebar selection state:** SwiftUI `List(selection:)` highlights the clicked row automatically. The currently-rendered detail view's playlist matches the highlighted sidebar row.
- **Back-button behavior:** `PlaylistDetailView`'s back button sets `selectedSection = .playlists`, returning the user to the grid (the grid then shows the playlist they were just in, available for re-tap from the card).

### 8-pin Soft-Limit Hint UI (D-10)

**Decision:** **Inline banner above the grid** in `PlaylistsView`. Slot between header bar and divider.

**Visual:**
```
┌──────────────────────────────────────────────────────────────────┐
│ ⚠  Pinned limit reached                                          │
│    Unpin one playlist before pinning another. (Maximum: 8)       │
└──────────────────────────────────────────────────────────────────┘
```
- Container: `HStack(spacing: 8)`, padding 12 horizontal / 8 vertical, background `Color.mlmRaised`, leading 3-pt-wide `Color.mlmWarning` rectangle (left accent bar).
- Icon: `Image(systemName: "exclamationmark.triangle.fill")`, 14 pt, `Color.mlmWarning`.
- Title: `MLMFont.bodyBold`, `Color.mlmInk`.
- Body: `MLMFont.muted`, `Color.mlmInkSecondary`.
- Position: directly under header bar, above the divider — pushes grid down by ~44 pt while visible.
- Auto-dismiss: **3 seconds** then disappears with `withAnimation(.easeInOut(duration: 0.2))`. State held in `viewModel.pinLimitHintMessage`.
- Manual dismiss: no close-X — auto-only (per macOS HUD/banner convention; persistent dismissable would be over-engineered for a 3-s hint).

**Where it does NOT appear:**
- Not on `PlaylistDetailView` (the user can't trigger a pin from there anyway).
- Not as an overlay over the sidebar.
- Not as an `NSAlert` modal.
- Not as inline-message-in-context-menu (context menus are dismissed too fast to read).

### Empty-Pinned Disclosure Group (D-08 default-expanded edge case)

When `pinnedPlaylists.isEmpty` AND `pinnedExpanded == true`:
- Show a single muted caption row inside the disclosure: "No pinned playlists" — `MLMFont.muted`, `Color.mlmInkMuted`, italic, padding 4 vertical / 16 leading (indent-matched).
- Row is **not selectable** (`.disabled(true)` or use `Text` not `Label`).
- When user pins their first playlist (anywhere in the app), the placeholder disappears and the pinned row replaces it — driven by `.onReceive(.playlistDidChange)` re-fetch.

### Sidebar Context Menu (D-11)

Order matches macOS conventions (most-frequent first, destructive last with separator):

```
Unpin from Sidebar          (⌘ no shortcut — discoverability sufficient)
Rename…                     (… because rename opens inline editor on the grid)
Reveal in Grid              (separator above)
─────
Delete                      (role: .destructive)
```

### Drop-Target Acceptance Rules

| Dragged item | Accepted? | Behavior |
|--------------|-----------|----------|
| Single image file from Finder (PNG, JPEG, HEIC, GIF, TIFF) | Yes | Center-crop to 512×512, save as PNG, set `cover_is_custom = 1` |
| Single image dragged from another app (`NSImage`) | Yes | Same as above |
| Multiple files | Yes — first file only; rest ignored silently | (No multi-cover concept) |
| Non-image file (e.g. `.txt`, `.mp3`, folder) | No — drop rejected | Banner: "Couldn't read that image. Try a PNG or JPEG file." |
| URL string (e.g. dragged from browser) | No — Phase 36 doesn't fetch remote URLs | Same rejection message |
