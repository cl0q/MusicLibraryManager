  <files>src-tauri/src/download/queue.rs, src-tauri/src/download/mod.rs</files>
  <action>
Create `src-tauri/src/download/queue.rs` implementing:

**QueueItem struct:**
- Fields:
  - `track_id: String` (unique identifier for track)
  - `query: String` (search query for YouTube fallback)
  - `source: String` ("dab" or "youtube")
  - `attempt_count: u32` (number of retry attempts)
  - `last_error: String` (error message from last failure)
  - `queued_at: String` (ISO 8601 timestamp)
- Derive: Serialize, Deserialize, Clone, Debug

**RetryQueue struct:**
- Fields:
  - `items: Vec<QueueItem>`
  - `max_attempts: u32` (default: 3 per user decision)
  - `queue_path: PathBuf` (file path for persistence)

**Methods:**
1. `fn new(queue_path: PathBuf) -> Self`
   - Initialize with empty items, max_attempts=3

2. `fn load(&mut self) -> Result<()>`
   - If queue file exists: read JSON, deserialize into items
   - If not exists: items remain empty (first run)
   - Reference RESEARCH.md "Pattern 4: Persistent Retry Queue"

3. `fn save(&self) -> Result<()>`
   - Serialize items to JSON with `serde_json::to_string_pretty`
   - Atomic write: write to temp file, rename to queue_path
   - Reference RESEARCH.md "Code Examples: Persistent Retry Queue with Serialization"

4. `fn add(&mut self, item: QueueItem)`
   - Check if item.attempt_count < max_attempts
   - If yes: add to items
   - If no: log warning "Max retries exceeded for {track_id}, dropping from queue"
   - Call save() after adding

5. `fn remove(&mut self, track_id: &str)`
   - Remove item matching track_id
   - Call save() after removing

6. `fn get_pending(&self) -> Vec<QueueItem>`
   - Return items where attempt_count < max_attempts

In `mod.rs`: Add `pub mod queue;` export.

Why max 3 attempts: User decision in 02-CONTEXT.md. Prevents unbounded queue growth from permanently failing tracks.
Why atomic write: Prevents corruption if app crashes mid-write. Temp file + rename is atomic on most filesystems.

<task type="auto">
  <name>Implement download orchestrator</name>
  <files>src-tauri/src/download/orchestrator.rs, src-tauri/src/download/mod.rs</files>
  <action>
Create `src-tauri/src/download/orchestrator.rs` implementing:

**DownloadRequest struct:**
- Fields:
  - `track_id: Option<String>` (for DAB)
  - `query: String` (search query for both DAB and YouTube)
  - `artist: String` (metadata for file organization)
  - `title: String`

**DownloadOrchestrator struct:**
- Fields:
  - `dab_client: DabClient`
  - `youtube_client: YoutubeClient`
  - `retry_queue: RetryQueue`
  - `flac_dir: PathBuf` (Lexar SSD path for FLAC originals)
  - `aac_dir: PathBuf` (temp staging for AAC transcodes)

**Methods:**
1. `async fn download_batch(&mut self, requests: Vec<DownloadRequest>) -> Result<BatchResult>`
   - Sequential processing (not parallel, per user decision):
     - For each request (index i):
       a. Emit progress: "Downloading Track {i+1}/{total}: {artist} - {title}..."
       b. Try DAB: `dab_client.download_stream(track_id, flac_path)`
         - If Success: proceed to transcode
         - If NotFound: proceed to YouTube fallback
         - If Error: add to retry queue, continue to next track
       c. If DAB returned NotFound, try YouTube: `youtube_client.search_and_download(query, flac_dir)`
         - If Success: proceed to transcode
         - If Error: add to retry queue, continue to next track
       d. Transcode: `transcode_audio(downloaded_file, aac_dir)`
         - If Transcoded: mark as complete
         - If Skipped: mark as complete (original kept)
         - If Failed: add to retry queue (keep FLAC, AAC marked pending)
       e. Update progress: "Completed {i+1}/{total}"
   - After batch: save retry queue to disk
   - Return BatchResult with success/failure counts

2. `async fn retry_failed(&mut self) -> Result<BatchResult>`
   - Load pending items from retry_queue
   - For each item:
     - Increment attempt_count
     - Retry download based on item.source (dab or youtube)
     - If succeeds: remove from queue
     - If fails: update last_error, save queue
   - Return BatchResult

**BatchResult struct:**
- Fields: `succeeded: u32`, `failed: u32`, `skipped: u32`

Reference 02-CONTEXT.md decisions:
- "Sequential downloads (one at a time) — simpler, avoids rate limits"
- "When both sources fail: queue for retry (don't block batch, don't lose track)"
- "Transcode failure: keep the original file, mark transcode as pending (don't re-download)"

In `mod.rs`: Add `pub mod orchestrator;` export.

Why sequential: User decision. Simplifies rate limiting, easier to debug, sufficient throughput for typical batches.

```rust
#[tauri::command]
async fn download_tracks(
    requests: Vec<DownloadRequest>,
    flac_dir: String,
    aac_dir: String,
) -> Result<BatchResult, String> {
    let mut orchestrator = DownloadOrchestrator::new(
        flac_dir.into(),
        aac_dir.into(),
    ).map_err(|e| e.to_string())?;

    orchestrator.download_batch(requests)
        .await
        .map_err(|e| e.to_string())
}
```

**Command 2: retry_failed_downloads**
```rust
#[tauri::command]
async fn retry_failed_downloads(
    flac_dir: String,
    aac_dir: String,
) -> Result<BatchResult, String> {
    let mut orchestrator = DownloadOrchestrator::new(
        flac_dir.into(),
        aac_dir.into(),
    ).map_err(|e| e.to_string())?;

    orchestrator.retry_failed()
        .await
        .map_err(|e| e.to_string())
}
```

**Command 3: get_retry_queue_status**
```rust
#[tauri::command]
async fn get_retry_queue_status(queue_path: String) -> Result<Vec<QueueItem>, String> {
    let mut queue = RetryQueue::new(queue_path.into());
    queue.load().map_err(|e| e.to_string())?;
    Ok(queue.get_pending())
}
```
