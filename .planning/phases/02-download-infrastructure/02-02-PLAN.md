<task type="auto">
  <name>Implement YouTube audio client</name>
  <files>src-tauri/src/download/youtube.rs, src-tauri/src/download/mod.rs</files>
  <action>
Create `src-tauri/src/download/youtube.rs` implementing:

**YoutubeClient struct:**
- Field: `yt_dlp_path: Option<PathBuf>` (path to yt-dlp CLI, None means use system PATH)

**Methods:**
1. `fn new() -> Result<Self>`
   - Verify yt-dlp CLI available: run `yt-dlp --version`
   - If not found, return error with message: "yt-dlp CLI not found. Install via: pip install yt-dlp"
   - Why: Fail fast with helpful error instead of cryptic runtime failures

2. `async fn search_and_download(&self, query: &str, output_dir: &Path) -> Result<YoutubeDownloadResult>`
   - Build yt-dlp command:
     - Search: `ytsearch1:{query}` (first result only, avoid ambiguity)
     - Format: `-f bestaudio` (best available audio quality, no minimum threshold per user decision)
     - Output: `-o "{output_dir}/%(title)s-%(id)s.%(ext)s"` (filename with video ID for uniqueness)
     - Extract audio: `-x` (extract audio from video container)
     - Keep video: `--keep-video` (if needed for debugging, optional)
   - Execute via yt-dlp crate wrapper
   - Parse output to get downloaded file path
   - Return `YoutubeDownloadResult::Success(PathBuf)` with final audio file path

3. `async fn download_by_url(&self, url: &str, output_dir: &Path) -> Result<YoutubeDownloadResult>`
   - Same as search_and_download but accepts direct YouTube URL instead of search query
   - Useful for manual fallback testing

**YoutubeDownloadResult enum:**
- `Success(PathBuf)` - audio file downloaded
- `NotFound` - no results for query (rare, but possible)

Reference RESEARCH.md "Don't Hand-Roll: yt-dlp integration" for rationale on using crate vs shell.

In `mod.rs`: Add `pub mod youtube;` export.

**Error handling:**
- yt-dlp process failures → propagate as errors (no retry logic here, orchestrator handles retries)
- Network timeouts → propagate as errors
- Invalid query → return NotFound

Why bestaudio: User decision accepts "best available" quality for YouTube fallback, no minimum threshold. Simplifies logic.
