  <files>src-tauri/src/download/client.rs, src-tauri/src/download/mod.rs</files>
  <action>
Create `src-tauri/src/download/client.rs` implementing:

**HttpClient struct:**
- Wraps `reqwest::Client` with retry configuration
- Method: `async fn get_with_retry(&self, url: &str) -> Result<reqwest::Response>`
  - Uses `backoff::future::retry` with `ExponentialBackoff::default()`
  - Classifies errors: 404 → permanent (don't retry), 429/5xx → transient (retry), network errors → transient
  - Returns response on success, propagates permanent errors immediately
  - Max 3 retry attempts with exponential backoff (1s, 2s, 4s intervals)

**RetryConfig struct:**
- Fields: `max_retries: u32`, `initial_interval: Duration`
- Default: 3 retries, 1s initial interval

Reference RESEARCH.md "Pattern 1: Backoff-Protected DAB API Calls" for backoff::Error::permanent vs transient classification.

In `mod.rs`: Add `pub mod client;` export.

Why backoff crate: Exponential backoff has subtle timing math (jitter, max intervals). Battle-tested crate eliminates retry loop bugs.

<task type="auto">
  <name>Implement DAB API client</name>
  <files>src-tauri/src/download/dab.rs, src-tauri/src/download/mod.rs</files>
  <action>
Create `src-tauri/src/download/dab.rs` implementing:

**DabClient struct:**
- Field: `client: HttpClient` (from client.rs)
- Base URL: `https://dabmusic.xyz/api`

**Methods:**
1. `async fn search_track(&self, query: &str) -> Result<Vec<DabTrack>>`
   - Endpoint: GET `/search/track?q={query}`
   - Returns parsed JSON array of tracks (title, artist, album, id)
   - Use `client.get_with_retry()` for automatic backoff

2. `async fn download_stream(&self, track_id: &str, output_path: &Path) -> Result<DownloadResult>`
   - Endpoint: GET `/stream/{track_id}`
   - Status code matching:
     - 200 → stream to file, return `DownloadResult::Success`
     - 404 → return `DownloadResult::NotFound` (triggers YouTube fallback)
     - Other → propagate error (retry handled by HttpClient wrapper)
   - Stream response body to disk using `futures_util::StreamExt` (don't load entire file into memory)
   - Atomic write: stream to temp file, rename to final path only on success
   - Delete partial file if download interrupted

**DabTrack struct:**
- Fields: `id: String`, `title: String`, `artist: String`, `album: String`
- Derive: Serialize, Deserialize

**DownloadResult enum:**
- `Success(PathBuf)` - file downloaded successfully
- `NotFound` - 404 from API (not an error, triggers fallback)

Reference RESEARCH.md "Pattern 2: Detect Not-Found vs Other Errors" for status code matching.
Reference RESEARCH.md "Pattern 5: Streaming Download with Progress" for chunked writing.

In `mod.rs`: Add `pub mod dab;` export.

Why streaming: Loading entire FLAC into memory causes OOM on large files. Streaming to disk is standard practice.
