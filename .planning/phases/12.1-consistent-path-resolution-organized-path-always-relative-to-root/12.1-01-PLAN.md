<objective>
Enforce the Phase 8-01 architectural invariant: organized_path is ALWAYS relative to library root, never absolute. This plan covers the two halves of enforcement:

1. Migrate existing data — 38 tracks in production have absolute paths (confirmed by audit: `/Volumes/Lexxar/Music/...`). Schema migration v9 strips the library root prefix via SQL UPDATE.
2. Harden write paths — replace the silent `unwrap_or_else` fallback in the download command with fail-fast error propagation, and add a `validate_organized_path()` guard in `update_download_status`.

Purpose: After this plan, no absolute paths can enter the database — neither from existing data nor from future downloads.
Output: Schema migration + hardened write path + unit tests for validation guard.
</objective>

Replace the silent fallback strip_prefix block (lines 124-133 currently) with fail-fast error propagation. The new block must:

1. Canonicalize both the absolute file path AND the root path before strip_prefix to resolve symlinks and normalize `..` segments.
2. Use `.map_err()` instead of `.unwrap_or_else()` so that a strip_prefix failure returns Err (download fails loudly, no silent absolute path storage).
3. Log the error before returning.

Replace:
```rust
let absolute = PathBuf::from(file_path);
let relative_path = absolute
    .strip_prefix(&root_path)
    .map(|p| p.to_string_lossy().to_string())
    .unwrap_or_else(|_| file_path.clone());
```

With:
```rust
let absolute = PathBuf::from(file_path);
// Canonicalize both paths to resolve symlinks before strip_prefix.
// If canonicalize fails (e.g. file doesn't exist yet), fall back to non-canonical strip.
let relative_path = {
    let canonical_root = root_path.canonicalize().unwrap_or_else(|_| root_path.clone());
    let canonical_abs = absolute.canonicalize().unwrap_or_else(|_| absolute.clone());
    canonical_abs
        .strip_prefix(&canonical_root)
        .map(|p| p.to_string_lossy().to_string())
        .map_err(|_| format!(
            "Downloaded file {} is outside library root {} — cannot store relative path. \
             Ensure download_dir and root_dir are consistent.",
            absolute.display(),
            root_path.display()
        ))?
};
```

The `?` propagates the error upward through the `for` loop and the outer function, causing `download_tracks` to return `Err(String)`. This is the correct behavior — fail fast rather than silently corrupt data.

  <action>
Add a Version 9 migration to the MIGRATIONS array in schema.rs. The migration reads the library root from app_config and strips it (plus trailing slash) from any organized_path that starts with that value.

SQLite does not have parameterized DDL in migrations, so use a two-statement approach that works portably:

```sql
-- Migration v9: Strip absolute library root prefix from organized_path.
-- Affects tracks where organized_path starts with the library root path stored in app_config.
-- Example: '/Volumes/Lexxar/Music/00_Artists/track.m4a' -> '00_Artists/track.m4a'
UPDATE tracks
SET organized_path = SUBSTR(
    organized_path,
    LENGTH((SELECT value FROM app_config WHERE key = 'library_root')) + 2
)
WHERE organized_path IS NOT NULL
  AND organized_path LIKE (SELECT value || '/%' FROM app_config WHERE key = 'library_root');
```

The `LENGTH(...) + 2` accounts for the trailing `/` after the root path. For example:
- root = `/Volumes/Lexxar/Music` (22 chars)
- organized_path = `/Volumes/Lexxar/Music/00_Artists/track.m4a`
- SUBSTR starts at position 24 (22 + 2 = 24), yielding `00_Artists/track.m4a`

Add this as the next entry in the MIGRATIONS array with version = 9 (check current max version first — the research says v8 is current, verify in the file). Also update the CURRENT_SCHEMA_VERSION constant if it exists.

After adding the migration, ensure the schema version check in the test at the bottom of the file (if any) is updated to expect v9.
