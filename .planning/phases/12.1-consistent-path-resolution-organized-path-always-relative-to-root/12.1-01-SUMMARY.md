# Phase 12.1 Plan 01: Consistent Path Resolution Summary

**organized_path absolute-path invariant enforced via validate_organized_path() guard, fail-fast strip_prefix in download_tracks, and schema migration v12 that strips existing absolute prefixes**

## Accomplishments

- Added `pub validate_organized_path()` in `database/tracks.rs` that rejects Unix absolute paths, Windows drive-letter paths, and `..`-traversal paths
- Wired validation guard into `update_download_status` so any DB write with an absolute organized_path returns `Err`
- Replaced silent `unwrap_or_else(|_| file_path.clone())` fallback in `download_tracks` with fail-fast `map_err + ?` that includes a clear error message
- Added schema migration v12 with SQL `UPDATE ... SET organized_path = SUBSTR(...)` to fix 38 production rows with absolute paths
- 355 lib tests pass, 0 failures

## Decisions Made

- Windows-style paths (`C:\...`) explicitly detected: `Path::is_absolute()` returns `false` on Unix for these, so a separate character-level check is needed
- `canonicalize()` is used with `unwrap_or_else` fallback: if the file doesn't exist at time of strip_prefix (rare edge case), the non-canonical path is still usable for the prefix strip
- Migration v12 is safe on fresh installs: the `WHERE ... LIKE (SELECT value || '/%' ...)` matches nothing if no library_root is set, so zero rows are updated
