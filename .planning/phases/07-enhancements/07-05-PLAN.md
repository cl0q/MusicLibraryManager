  <name>Task 1: Implement fingerprint-based duplicate detection with review queue</name>
  <files>

  <action>
    1. Create `src-tauri/src/dedup/fingerprint.rs`:
       a. Define ReviewQueueEntry struct:
          ```rust
          pub struct ReviewQueueEntry {
              pub action_type: String,     // "fingerprint_dedup" | "metadata_conflict"
              pub track_id: i64,
              pub related_track_id: Option<i64>,
              pub details: String,         // JSON string
              pub auto_action: Option<String>, // "kept_higher_quality" | "flagged"
          }
          ```

       b. `fn add_to_review_queue(conn: &Connection, entry: &ReviewQueueEntry) -> Result<i64>`:
          - INSERT INTO review_queue (action_type, track_id, related_track_id, details, auto_action, status)
          - Return the new row ID

       c. `fn detect_fingerprint_duplicates(conn: &Connection, track_id: i64) -> Result<Vec<(i64, f64)>>`:
          - Load fingerprint for track_id from database
          - Load all other fingerprints (excluding track_id)
          - Compare using fingerprint::matcher::compare_fingerprints
          - Return Vec of (matching_track_id, score) where score >= 0.4
          - Sort by score descending

       d. `fn process_fingerprint_duplicate(conn: &Connection, track_id: i64, duplicate_id: i64, score: f64) -> Result<()>`:
          - Get both tracks from database
          - Determine which is better quality (use existing duplicate module's quality comparison: lossless > lossy, then bitrate)
          - If metadata substantially differs (title or artist don't fuzzy match above 0.7): FLAG for review, don't auto-merge
            - Create ReviewQueueEntry with action_type "metadata_conflict", auto_action "flagged"
            - Details JSON: { "score": score, "track_1": { id, title, artist, quality }, "track_2": { id, title, artist, quality }, "reason": "metadata_differs" }
          - If metadata agrees: auto-keep best quality, mark worse as duplicate
            - Mark lower quality track's is_duplicate = 1 and variant_of = better_track_id
            - Create ReviewQueueEntry with action_type "fingerprint_dedup", auto_action "kept_higher_quality"
            - Details JSON: { "score": score, "kept": { id, title, quality }, "marked_duplicate": { id, title, quality } }

       e. `fn deep_scan_library(conn: &Connection) -> Result<DeepScanResult>`:
          - Get all tracks with fingerprints
          - Compare all pairs (O(n^2) but acceptable for initial implementation)
          - For each pair above threshold: call process_fingerprint_duplicate
          - Skip pairs where one track is already marked as duplicate
          - Return DeepScanResult { pairs_compared: usize, duplicates_found: usize, conflicts_flagged: usize }

       f. `fn get_review_queue(conn: &Connection, status: Option<&str>) -> Result<Vec<ReviewQueueRow>>`:
          - SELECT * FROM review_queue WHERE status = ? (or all if None)
          - Return parsed rows with details JSON

       g. `fn resolve_review_item(conn: &Connection, review_id: i64, action: &str) -> Result<()>`:
          - UPDATE review_queue SET status = ?, resolved_at = CURRENT_TIMESTAMP WHERE id = ?
          - action: "approved" | "rejected" | "dismissed"

    2. Update `src-tauri/src/dedup/mod.rs`:
       - Add `pub mod fingerprint;`
       - Re-export: detect_fingerprint_duplicates, deep_scan_library, get_review_queue, resolve_review_item

       - test_process_fingerprint_duplicate_auto_keeps_quality: two tracks with same fingerprint and similar metadata, different quality, should mark lower quality as duplicate
       - test_deep_scan_skips_existing_duplicates: tracks already marked is_duplicate should not be re-processed

<task type="auto">
  <name>Task 2: Integrate fingerprinting into import pipeline</name>
  <files>

  <action>
    1. Modify `src-tauri/src/import/scanner.rs` to add fingerprinting after successful import:
       - After a batch of tracks is imported (existing batch_import function), fingerprint each newly imported track
       - This should be BEST-EFFORT: if fingerprinting fails for a track, log a warning but don't fail the import
       - Pattern:
         ```rust
         // After successful import of a track:
         // Fingerprint the new track (best-effort, non-blocking)
         if let Ok((fp, duration)) = crate::fingerprint::chromaprint::fingerprint_track(Path::new(&track.metadata.original_path)) {
             if let Err(e) = crate::fingerprint::chromaprint::save_fingerprint(conn, track_id, &fp, duration) {
                 log::warn!("Failed to save fingerprint for track {}: {}", track_id, e);
             }
             // Check for fingerprint duplicates
             if let Ok(dups) = crate::dedup::fingerprint::detect_fingerprint_duplicates(conn, track_id) {
                 for (dup_id, score) in dups {
                     if let Err(e) = crate::dedup::fingerprint::process_fingerprint_duplicate(conn, track_id, dup_id, score) {
                         log::warn!("Failed to process fingerprint duplicate for track {}: {}", track_id, e);
                     }
                 }
             }
         } else {
             log::warn!("Failed to fingerprint track during import: {}", track.metadata.original_path);
         }
         ```

       - NOTE: Fingerprinting is CPU-intensive (decodes entire audio file). For large imports, this will slow things down. This is acceptable because:
         a. The import already processes files one at a time
         b. User expectation is set by the CONTEXT.md decision: "Fingerprint on import (auto)"
         c. For very large libraries, the user can do a manual deep scan later

    2. Ensure that the import function's existing tests still pass. The fingerprinting calls should not break the existing test setup because they will fail gracefully (test files aren't real audio).

    3. Add a comment in the code marking where the fingerprint-on-import integration point is, so it's easy to find and adjust.

    4. Unit test:
       - test_import_continues_on_fingerprint_failure: verify that importing a file with invalid audio content (can't be decoded) still succeeds as an import — the fingerprint failure is logged but doesn't block.
