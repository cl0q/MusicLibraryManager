Create `src-tauri/src/database/playlist.rs` with fractional indexing helpers:

1. **position_between function:**
   - Signature: `fn position_between(left: Option&lt;&str&gt;, right: Option&lt;&str&gt;) -&gt; Result&lt;String&gt;`
   - Use string-based fractional indexing (base-95 alphabet: ASCII 32-126 excluding delimiter "|")
   - Cases:
     - (None, None) → "a0" (first position)
     - (Some(left), None) → append "|a0" to left (insert after)
     - (None, Some(right)) → "a0" if right > "a0", else compute midpoint
     - (Some(left), Some(right)) → compute midpoint string between left and right
   - Implementation: Use string comparison and character insertion (no precision limits)
   - Reference: Research.md Pattern 1 for algorithm details

2. **Helper: increment_position_string:**
   - Generates next position by appending "|a0" to current
   - Used when inserting at end of playlist

3. **Helper: midpoint_position_string:**
   - Computes string midpoint between two positions
   - Example: midpoint("a0", "a1") = "a0|m0" (lexicographically between)
   - Use character arithmetic with base-95 alphabet

Include unit tests for position_between covering all cases:
- Empty playlist (None, None)
- Insert at end (Some, None)

- Insert between two positions (Some, Some)
- Verify lexicographic ordering: left &lt; result &lt; right

Add playlist CRUD operations to `src-tauri/src/database/playlist.rs`:

1. **create_playlist:**
   - Parameters: conn (&amp;Connection), name (String), description (Option&lt;String&gt;), tags (Vec&lt;String&gt;), category (PlaylistCategory)
   - Use transaction pattern: `conn.transaction()?`
   - Insert into playlists table with category, is_liked=0, is_smart=0, is_pinned=0
   - For each tag in tags, insert into playlist_tags table
   - Return playlist_id
   - Include test: create playlist with tags, verify both tables populated

2. **add_track_to_playlist:**
   - Parameters: conn (&amp;Connection), playlist_id (i64), track_id (i64)
   - Query last position: SELECT position FROM playlist_tracks WHERE playlist_id = ? ORDER BY position DESC LIMIT 1
   - Generate new position: position_between(last_position, None) to append
   - Insert into playlist_tracks with UNIQUE constraint (playlist_id, track_id)
   - Use PRAGMA foreign_keys = ON at start of transaction
   - Include test: add 3 tracks, verify positions are ordered ("a0", "a0|a0", "a0|a0|a0")

3. **remove_track_from_playlist:**
   - Parameters: conn (&amp;Connection), playlist_id (i64), track_id (i64)
   - DELETE FROM playlist_tracks WHERE playlist_id = ? AND track_id = ?
   - Do NOT update positions of remaining tracks (fractional indexing advantage)
   - Include test: remove middle track, verify positions of other tracks unchanged

4. **reorder_playlist_track:**
   - Parameters: conn (&amp;Connection), playlist_id (i64), track_id (i64), target_position (Option&lt;i64&gt; for target track ID or None for end)
   - If target_position is Some: query positions of target and its predecessor, compute midpoint
   - If target_position is None: query last position, append
   - UPDATE playlist_tracks SET position = ? WHERE playlist_id = ? AND track_id = ?
   - Only 1 row updated (O(1) database operation)
   - Include test: reorder 5 tracks via drag-drop, verify only moved track's position changed

5. **get_playlist_tracks:**
   - Parameters: conn (&amp;Connection), playlist_id (i64)
   - SELECT t.* FROM tracks t JOIN playlist_tracks pt ON t.id = pt.track_id WHERE pt.playlist_id = ? ORDER BY pt.position
   - Return Vec&lt;Track&gt; (use existing Track model from models/mod.rs)
   - Include test: verify tracks returned in correct order after reordering
