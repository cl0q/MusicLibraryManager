## Component Contract

### TrackCoverView (NEW)

Custom SwiftUI view for displaying track artwork across all surfaces.

**Props:**
```swift
struct TrackCoverView: View {
    let trackId: Int64
    let size: ArtworkService.ArtworkSize  // .small (40pt) or .large (56-128pt)
    var cornerRadius: CGFloat = 6          // Default 6pt; can be overridden
}
```

**Behavior:**
1. **Initialization:** Loads from cache (NSCache) → if miss, async load from disk (FileManager).
2. **While loading:** Displays fallback gradient + centered music.note icon.
3. **On arrival:** Renders artwork image, dismisses fallback.
4. **Notification observance:** Listens to `.trackArtworkDidChange` notification. If `userInfo["trackId"]` matches, invalidates cache + reloads.
5. **File-existence check (D-14):** If DB says artwork exists but file is missing (user cleared cache), triggers self-healing via `ArtworkBackfillService.refreshSingleTrack()`. While backfill is pending, renders fallback.

**Fallback rendering:**
```
RoundedRectangle(cornerRadius: cornerRadius)
  .fill(LinearGradient(
    gradient: Gradient(colors: [.mlmBase, .mlmRaised]),
    startPoint: .topLeading,
    endPoint: .bottomTrailing
  ))
  .overlay(
    Image(systemName: "music.note")
      .foregroundStyle(.mlmInkMuted)
      .font(.system(size: sizePoints / 2))
  )
```

**No placeholder skeleton.** During load phase, fallback is visible immediately (same as empty state).

## Surface Specifications

### Surface 1: LibraryTable — Title Column (MODIFY)

**Current state (Phase 36):** Title column contains text title only. `isNowPlaying` indicator shown separately (animated speaker.wave.2 icon in green when track is playing).

**Phase 37 change (D-13):**
- Add `TrackCoverView` inline **left of** title text, in same HStack.
- New column structure: `HStack(spacing: 8) { TrackCoverView ; nowPlayingIndicator? ; Text(title) }`

**Dimensions:**
- Thumbnail size: 18pt (ArtworkService.ArtworkSize.small equivalent)
- Source image: `{trackId}_500.jpg` (loaded via TrackCoverView with size: .small)
- Corner radius: 4pt (compact for table context)

**Spacing:**
- Gap between cover and nowPlayingIndicator: 8px (md token)
- Gap between indicator and title: 8px (md token)
- Fallback gradient visible during load; no skeleton loader.

**Layout constraint:**
- Title column min-width currently 140px. Ideal width may increase slightly if visually cramped (planner discretion per D-13 note).
- Cover + indicator + title must fit within column width; if cramped, grow ideal-width from 260px to accommodate 18pt cover + gaps + text without truncation.

**Interaction:**
- Cover is **not interactive** (click routes to row selection as normal, not to cover-specific action).
- No right-click context menu on cover (uses parent row's context menu).

**Accessibility:**
- Alt text: Image label = track title (inherited from row, not duplicated).
- Cover has no dedicated a11y announcement (title and metadata are in text).

## Loading States

All three surfaces follow the same loading state pattern:

**State flow:**
1. **Initial (before artwork available):** Render fallback gradient + music.note icon
2. **Load in progress:** Fallback remains visible (no spinner overlay; async load is silent)
3. **Success:** Image appears, fallback is replaced
4. **Failure (file not found after async load):** Fallback remains visible; if DB row exists but file missing, trigger self-healing re-backfill (silent, no error banner)
5. **Failure (ffmpeg not installed at extraction time):** Silent (ArtworkBackfillService logged a warning; user never sees this failure at render time because TrackCoverView receives nil and renders fallback)

**No error state copy needed.** Fallback visual is the error state.

---

## Animation & Transitions

**Image fade-in on arrival:** When artwork loads from disk or cache, fade in over 0.2s (planner discretion on easing curve; suggest `.easeIn`). Fallback gradient remains beneath during fade-in (no flashing).

**Notification-triggered reload:** When `.trackArtworkDidChange` fires for this track, invalidate cache + reload. Fade-out old image (0.1s), load fallback temporarily, fade-in new artwork (0.2s). **Total duration: <300ms** to feel responsive.

**No looping or repeating animations.** Covers are static once loaded.

## Accessibility

**Color contrast:**
- Fallback gradient (mlmBase → mlmRaised) must meet WCAG AA contrast ratio vs text overlays. Verified in Phase 36 Solar palette validation (CONTRAST in CONTRACT.md).
- Music.note icon (mlmInkMuted foreground) must have sufficient contrast against gradient. If not, planner escalates to design review.

**Keyboard navigation:**
- Covers are non-interactive (no keyboard focus).
- Parent table row / detail view remains keyboard-navigable (unchanged).

**Screen reader:**
- Table row already announces title, artist, format via Text elements; cover adds no extra verbosity.
- Detail view announces title, artist, format; cover adds no extra verbosity.
- PlayerBar announces "Now playing: [title] by [artist]"; cover adds no extra verbosity.

**Resize handling:**
- All three surfaces use fixed aspect-ratio squares (no overflow or clipping on resize).
- Corner radius remains fixed (no dynamic adjustment based on size).

## Responsive Behavior

**LibraryTable column:**
- Cover size is fixed at 18pt (no scaling with column width).
- If column width < 160px (cover + gaps + min title width), column grows horizontally.
- No responsive hiding of cover at narrow widths (table never gets narrow enough on macOS; minimum window width is enforced elsewhere).

**TrackDetailView:**
- Cover size fixed at 56pt (or 128pt per ROADMAP criterion, planner decides). Centered on screen, not responsive.
- No mobile/tablet considerations (macOS desktop only).

**PlayerBar:**
- Cover size fixed at 40pt. Always visible (mini bar is always on screen). Never hidden or scaled down.

## Validation & Testing

### Smoke Test Checklist

Before `/gsd-verify-work`:
1. Import a track with embedded artwork (FLAC, MP3 with APIC/METADATA_BLOCK_PICTURE).
2. Verify cover appears in LibraryTable within 2 seconds (background backfill).
3. Verify cover appears in TrackDetailView header when track is selected.
4. Verify cover appears in PlayerBar when track is playing.
5. Click "Play" on a track; verify PlayerBar cover matches detail view cover.
6. Delete `~/Library/Caches/com.mlm.artwork_cache/` folder (simulate user cache cleanup).
7. Scroll table; verify covers re-load from disk and appear within 200ms (after self-healing backfill).
8. Manually clear artwork DB row; verify fallback gradient renders in all surfaces (no crashes).

### Visual Regression Prevention

- Snapshot tests for TrackCoverView in isolation (fallback state + image state).
- Snapshot tests for LibraryTable row with cover (18pt, alongside title + indicator).
- Snapshot tests for TrackDetailView header (56pt or 128pt, depending on ROADMAP).

## Notes for Planner

1. **ROADMAP success criterion #3** ("TrackDetailView header 56-128pt") — decide size growth during planning. Current contract uses 56pt baseline; if 128pt is mandated, update corner radius and layout as needed.

2. **`refreshSingleTrack()` vs `refreshMissing()`** — TrackCoverView calls `ArtworkBackfillService.refreshSingleTrack(trackId:)` on file-miss detection. Ensure this method exists and is idempotent (planner to define in PLAN.md).

3. **Notification batching (D-03, Pitfall 4)** — Contract specifies per-track `.trackArtworkDidChange` notifications, but if performance testing shows table re-renders lag, planner can batch notifications (e.g., every 50 tracks) at ArtworkBackfillService level. Views would debounce accordingly.

4. **MaintenanceView button split (D-16)** — Two buttons for Settings Maintenance:
   - "Refresh embedded artwork" → `ArtworkBackfillService.refreshMissing()`
   - "Fetch from MusicBrainz" → old `ArtworkService.batchFetchArtwork()` path
   - Planner to define UI layout and success criteria for both paths.

5. **TrackCoverView cache invalidation** — Ensure `.trackArtworkDidChange` notification invalidates **all sizes** for a track in `TrackArtworkCache` (not just .small or .large). Planner to document in code.
