  <files>src-tauri/src/database/schema.rs</files>
  <action>
Add Phase 5 schema migration to schema.rs following established pattern:

1. Update CURRENT_SCHEMA_VERSION constant from 3 to 4
2. Add PHASE5_SCHEMA_SQL constant with five tables:

**sync_profiles table:**
- id (INTEGER PRIMARY KEY)
- name (TEXT NOT NULL UNIQUE) — Profile display name
- output_folder (TEXT NOT NULL) — Local staging folder path
- date_created (TEXT DEFAULT CURRENT_TIMESTAMP)
- date_modified (TEXT DEFAULT CURRENT_TIMESTAMP)

**sync_profile_tracks table:**
- profile_id (FK to sync_profiles)
- track_id (FK to tracks)
- PRIMARY KEY (profile_id, track_id)
- Purpose: Manually added individual tracks

**sync_profile_playlists table:**
- profile_id (FK to sync_profiles)
- playlist_id (FK to playlists)
- PRIMARY KEY (profile_id, playlist_id)
- Purpose: Include all tracks from selected playlists

**sync_profile_rules table:**
- id (INTEGER PRIMARY KEY)
- profile_id (FK to sync_profiles)
- field (TEXT NOT NULL) — "genre" | "source" | "date_added" | "artist" | "bitrate" | "tag"
- operator (TEXT NOT NULL) — "eq" | "ne" | "gt" | "lt" | "contains" | "in"
- value (TEXT NOT NULL) — Filter value
- Purpose: Query-based track selection

**sync_state table:**
- id (INTEGER PRIMARY KEY)
- profile_id (FK to sync_profiles)
- track_id (FK to tracks)
- synced_checksum (TEXT) — SHA256 of transcoded file at sync time
- synced_size (INTEGER) — File size in bytes
- synced_timestamp (TEXT) — ISO 8601 timestamp
- UNIQUE(profile_id, track_id)
- Purpose: Incremental sync state tracking

3. Add migration function apply_phase5_migration following Phase 3/4 pattern
4. Update ensure_schema to call Phase 5 migration when version < 4

Follow established patterns:
- Foreign keys with ON DELETE CASCADE
- Indexes on frequently queried columns
- TEXT for timestamps (ISO 8601)
- INTEGER for boolean flags (1/0)
